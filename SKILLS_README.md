## Як поставити (2 хвилини)

1. Розпакуй архів.
2. Скопіюй теку `.claude/` у **корінь** нового репозиторію.
3. Закоміть і запуш:
   ```
   git add .claude && git commit -m "chore: скіли Claude" && git push
   ```
4. Відкрий новий чат Claude Code у цьому репозиторії — скіли підхопляться самі.
   Перевірка: набери `/` — у списку мають зʼявитись `/audit`, `/mockup`, `/fix`.

> ⚠️ **Скіли підхоплюються ТІЛЬКИ з кореня репозиторію.** Якщо покласти `.claude/`
> у підпапку — Claude їх не побачить.

## Чого тут НЕМА і чому

- **`caveman`** — режим стислого спілкування, жорстко прописаний під CSTL NEWS
  українською. Перенести можна, але його треба переписувати цілком.
- **`/startuem`, `/finish`, `/onovy`, `/byyou`** — вони зав'язані на структуру
  документації CSTL (`NOW.md`, `HOT_RULES.md`, `SESSION_STATE_VOVA.md`).
  У порожньому репозиторії просто впадуть. Для СТО такі команди треба **писати заново**
  під нову документацію — це окрема робота.
- **`/ai-seo`, `/seo-audit`, `/social`, `/copywriting`, `/content-strategy`,
  `/community`, `/launch`, `/marketing-ideas`, `/analytics`** — усі про медіа-платформу
  для Олики. Для СТО в Англії їх треба переписувати з нуля (інша мова, інша аудиторія,
  інша послуга), а не переносити.
- **хуки (hooks — автоматичні перевірки)** — у CSTL вони прописані з **абсолютним
  шляхом** `/home/user/CSTL_NEWS/...`. У новому репозиторії зламаються мовчки.
  Переносити тільки з переписаними шляхами.

## 🔴 Пастка, якої тут уже немає

У `CSTL_NEWS` сім із цих скілів лежать **не як файли, а як симлінки** (symlink —
«ярлик», файл-вказівник на інше місце) з `.claude/skills/` у `.agents/skills/`.

Якби ти скопіював теку `.claude/` напряму — у новому репозиторії ти отримав би
**сім битих ярликів**, які вказують у нікуди, і скіли мовчки не працювали б.

У цьому пакеті ярлики **розіменовані** — усередині справжні файли. Перевірено:
симлінків 0.
