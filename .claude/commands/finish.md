# /finish — завершити сесію і злити роботу в `main`

**Коли:** робота готова, Вова перевірив і сказав, що фіксуємо.

🛑 **Не плутати з передачею в новий чат.** `/finish` **публікує**. Якщо треба
просто передати контекст наступному чату — онови `NOW.md` і журнал, і все.

---

## 1. Звірка перед злиттям

```
git status --short                      # незакоміченого бути не має
git fetch origin
git log --oneline HEAD ^origin/main     # що піде в PR
```

🛑 **Якщо є незакомічене — спершу закоміть.** Незапушене = втрачене.

## 2. Злиття `main` У ГІЛКУ (а не навпаки)

```
git merge origin/main
```

🔴 **Конфлікти розбирай по одному.** ❌ Ніколи `-X theirs` / `-X ours` —
це мовчки викидає чужу роботу.

## 3. Перевірка

- сторінка відкривається, форма заявки шле;
- перевірити **на телефоні** — більшість клієнтів прийде з мобільного;
- `/audit`, якщо змін було багато;
- **`vibe-audit`** перед публікацією: ключі, `.env`, персональні дані.

🛑 **Не пиши «готово», поки не побачив exit 0.**

## 4. Оновити документацію

- **`NOW.md`** — 🔴 обовʼязково: що зроблено, що не доробили, що далі.
  Чесно про недороблене: наступний чат читає це як істину.
- журнал сесії `_session-log/` — дописати підсумок.

## 5. PR і злиття

```
git push -u origin <гілка>
```
Далі PR у `main` → **squash merge** (усі коміти гілки стискаються в один).

## 6. Фінальна звірка

```
git fetch origin
git log --oneline HEAD ^origin/main      # має бути 0
```

**Звіт Вові:** що злито · що лишилось недоробленим · що перевірити пальцем.
