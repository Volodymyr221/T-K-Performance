від 05.09.2026, і воно визначає всю архітектуру.

`J.W · …318` замість «James Whitlock». Нам імена не потрібні, а СТО
спокійніше.

## Інтерфейс — запустити

Просто відкрити `crm/app/index.html` через будь-який локальний сервер:

```bash
python3 -m http.server 8099
# → http://127.0.0.1:8099/crm/app/index.html
```

Через `file://` не працює: шрифти сайту лежать на два рівні вище.

**Три екрани:** Сьогодні (розклад + заявки з сайту) · Клієнти (список і
картка з атрибуцією) · Звіт (комісія, панель «Що НЕ рахували»).

**Перемикач «Дивимось очима»** у лівій колонці міняє роль — видно, що
саме зникає з екрана в механіка й у партнера.

## Запустити локально — 6 команд

Потрібен PostgreSQL 15+ (перевірено на 16.13).

```bash
# 1. Порожній кластер у тимчасовій теці
initdb -D /tmp/pgtest/data -A trust -E UTF8 --locale=C

# 2. Підняти на окремому порту, щоб не заважати нічому іншому
pg_ctl -D /tmp/pgtest/data -o '-k /tmp/pgtest -p 5433' -l /tmp/pgtest/log start

# 3. База
createdb -h /tmp/pgtest -p 5433 tkcrm

# 4. Міграції по порядку
for f in crm/migrations/0*.sql; do
  psql -h /tmp/pgtest -p 5433 -d tkcrm -v ON_ERROR_STOP=1 -f "$f"
done

# 5. Злий тест прав доступу
psql -h /tmp/pgtest -p 5433 -d tkcrm -f crm/tests/rls_test.sql

# 6. Прибрати за собою
pg_ctl -D /tmp/pgtest/data stop
```

**`ON_ERROR_STOP=1` обовʼязково.** Без нього `psql` ковтає помилку, друкує
її в потік і повертає код 0 — тобто скрипт скаже «все добре» на зламаній
базі. Я на це вже наступив.

## Що показує перевірка

Після сіду комісій **ніхто не вставляв руками** — їх нарахував тригер:

```
  status  |     reason      | jobs | total
----------+-----------------+------+--------
 due      | —               |    7 | 454.60
 excluded | below_threshold |    1 |   0.00
 excluded | not_our_source  |    2 |   0.00
 excluded | pre_existing    |    1 |   0.00
 excluded | window_expired  |    1 |   0.00
```

Порожньо → логіка з `0002` не працює.
Немає рядків `excluded` → панель «Що НЕ рахували» у звіті буде брехати.

Злий тест прав — **28 перевірок, усі PASS**:

| хто | що НЕ бачить |
|---|---|
| механік | комісії · ставки · аудит · звіт партнера |
| приймальник | комісії · ставки |
| **партнер** | **імена клієнтів · авто · заявки · склад працівників** |
| анонім з публічним ключем | взагалі нічого |

## Про ключі Supabase — щоб не злякатись

| ключ | куди | секрет? |
|---|---|---|
| `anon` (публічний) | 🟢 прямо в код фронтенду | **ні**, публічний за задумом |
| `service_role` | тільки сервер | 🔴 **так**. У фронт — ніколи |

Публічний ключ нічого не відкриває — він лише каже «звертаюсь до цього
проєкту». Що саме віддадуть, вирішує RLS. Тому в репозиторії він може
лежати відкрито; злий тест вище саме це й доводить.

## 🪤 Пастки, знайдені на практиці

- **`to_char()` не `IMMUTABLE`** — індекс на `to_char(done_on,'YYYY-MM')`
  Postgres будувати відмовляється. Вибірка за місяць іде діапазоном дат.
- **Власник таблиць обходить RLS завжди.** Тестувати права треба під
  окремою роллю (`app_user`), інакше тест показує PASS там, де діра.
- **`SET LOCAL` поза транзакцією мовчки не діє** — лише попередження в лог.
  Тест при цьому виконується від суперкористувача і бреше.
- **`psql` без `ON_ERROR_STOP=1` повертає 0 на помилці.**
- **`numeric`, ніколи не `float`** для грошей. `float` дає `274.99999999996`.
